# 검증 기록과 남은 문제

기록일: 2026-10-23. 사용자 Ubuntu 실행 화면을 통해 확인한 기록입니다.
재현 자동 수집 로그나 반복 통계가 없는 항목은 수동 관찰로 표시합니다.

## 로컬 검사

`python3 -m unittest -v test_shelf test_sim_assets`: 26개 통과.

- 지점 매핑·좌표 미등록·지도 불일치·잘못된 좌표 거부
- 일치/불일치/미등록/복수/미검출 마커
- 이전 관측 배제·연속 확인·단절·기한·요청 재시도
- /clock과 영상의 작은 수신 순서 차이, 큰 차이·중복·오래된 영상 거부
- 생성 월드 XML·접근 좌표 방향·지도 픽셀 구조

자산 구조 검사에 쓰는 격자는 유효한 ArUco 패턴이 아닙니다.
이 검사는 기하/직렬화를 검사하며 실제 검출 성능 검사는 아닙니다.

적재·하역 및 Task Manager의 전체 물류 임무 상태 전환은 시험 범위가 아닙니다.

## 수정한 문제

1. Nav2 launch의 소문자 false가 Python 식으로 평가됨: False로 수정.
2. tf2/tf2_ros 0.25.23에서 AMCL 활성화 문제: 0.25.24 업데이트 뒤 활성화 확인.
   공식 변경 기록에 교착 수정이 있지만 실행 로그만으로 모든 원인을 단정하지 않습니다.
3. 영상 source_age_seconds=-0.055로 최신 영상이 거부됨: /clock 수신 순서 차이를
   0.1초까지 허용하고 나머지 시각 검사는 유지. 수정 후 A 재검증, C/배송 검증 성공.
4. Nav2 준비 직전 목표 거절: 준비된 뒤 재실행하면 이동 성공.
   게시용 sim_mission.py에는 lifecycle 활성화 대기를 추가했습니다.
   이 추가 대기 코드는 문법 검사만 완료했으며 변경 후 ROS 재실행은 필요합니다.

## 남은 문제와 검증 필요

- 주행 중 Message Filter/TF too old 경고가 여전히 관찰됨.
- 실제 TurtleBot3 카메라/지도/조명/마커 크기·사전으로 검증하지 않음.
- 팀 Task Manager와 메시지 규격은 합의 및 연결 전.
- 실제 마커 지도 좌표를 이용한 TF2/AMCL 자동 초기화는 다른 역할이며 이 모듈에서 구현하지 않음.
- 기본 실물용 registry의 접근 좌표는 미등록. 생성된 좌표는 Gazebo 전용.
